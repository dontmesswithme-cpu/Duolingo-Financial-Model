## Active Audit Learnings & Quality Rules

<!-- OP appends real accumulated audit learnings below during development -->

- [P1.2] [Data Integrity] AUDIT BUG: DS build-tool matched statement labels by substring-anywhere and fell through to the next row containing the substring when the true row's cell was a dash — emitting a bottom-line total as a different metric. -> AUDIT RULE: value verification must be COLUMN-PINNED (value at row×period-column) against the filing, never string-somewhere-in-table; an em-dash in the filing must never appear as a dataset value.
- [P1.2] [Verification Blind Spot] AUDIT PATTERN: statement-identity recomputation (A=L+E, sums of components) cannot catch phantom rows that participate in no recomputed sum — only filing-value column-pinned re-verification catches them. Keep both lanes; never rely on identities alone for data sub-phases.
- [P1.2] [Submission Honesty] AUDIT RULE: a submission/log claim that contradicts the shipped dataset (e.g. "no such row emitted" when one exists) is itself a rejection condition — always re-derive the claims, not just the numbers.
- [P1.4] [Fixture Trust] AUDIT BUG: DS hand-built KPI fixtures from IR-letter headline figures, then dataset + fixtures agreed — suite 223/223 green while 3 values were wrong vs the cited filings. -> AUDIT RULE: green tests validate internal consistency, not external truth. When the SAME party generates data and fixtures from one (wrong) source, only an independent re-pull of the cited document can break the circle. At data gates, always verify a sample of fixture values against the filing BEFORE trusting suite greenness.
- [P1.4] [Source Discipline] AUDIT RULE: a figure may only be transcribed into a row citing document X if it is X's own figure. IR-letter/headline values (e.g. December single-month MAU 147.6M) must never fill rows citing the 10-K (which files the 3-month average 133.1M). If the letter value is wanted, it needs its own IR ledger entry + citation.
- [P1.4] [Verbatim Definitions] AUDIT RULE: "verbatim definition" means verbatim from the document the row CITES, per row — not "verbatim from some document". Filings revise definition wording across periods (measurement-period sentences, definition-update sentences, product-era names like "Duolingo Plus"); a single shared definition string across multiple cited docs is a false-citation defect by construction. Fixture maps must be keyed per document.
- [P1.4] [Reported-State Integrity] AUDIT RULE: reconciliation notes may only use figures that exist in filings or the dataset. Back-solved numbers presented as filed figures ("EXACT MATCH" claims built on 872,947 which appears in no filing) are a reported-state integrity violation — grep claimed filing values against the cached filings before accepting any "exact match" claim.
- [P2.1] [Contract-Basis Fixture Echo] AUDIT BUG: engine silently fell back (`ttmRev?.value ?? quarterlyValue ?? 0` + try/catch swallow) to a 3-month quarterly denominator where the contract mandated TTM, and the new fixture was written by dividing by the same quarterly figure the engine used — suite fully green (246/246), contract broken, output financially meaningless (169.2% deferred-revenue ratio vs correct ~44% on TTM basis). -> AUDIT RULE: whenever a contract names a specific computation basis (TTM, annualized, per-period), the audit must independently resolve THAT basis from the corpus and compare against engine output — and never accept a fixture whose derivation basis wasn't independently checked. Silent-basis fallbacks (`?.value ?? alternative ?? 0`) in engine code are fail-closed violations: unresolvable contract inputs must throw typed EngineError, never degrade to green-but-wrong output.
- [P2.1] [TTM Prerequisites] AUDIT PATTERN: TTM resolution for a flow metric requires all 4 window quarters to be derivable — which requires YTD rows from 10-Qs (or discrete quarters) for EVERY window quarter. A corpus of discrete quarters + annuals alone (no YTD) leaves the oldest-quarter-minus-Q4 window unresolvable. Before accepting any TTM-dependent schedule, probe `ttm.compute(historical).byMetric` for the specific denominator metric and assert it RESOLVED (probe: `scratch/op_probe_p2_1.mjs` §3 pattern — print basis verdict, never assume).
- [P2.1] [Watcher Re-Arm Race] AUDIT PATTERN: a re-armed watcher baselines on the CURRENT seq at re-arm time — if the partner's flip already happened (or lands during the audit window), the watcher waits on a seq that will never come and both agents burn the full 2h timeout. Signature: "timeout + inbox/seq reconciliation balanced + partner's last state = halted/§4.2-recovered". -> RULE: on every watcher wake/timeout, reconcile inbox blocks vs seq BEFORE concluding anything; when issuing a verdict, if the partner is in a halted/§4.2 state, expect the verdict to land cold — the Director must prompt the partner's next session; do not re-arm against a halted partner (no loop-polling).
- [P2.1-R1] [Semantic Key Consistency] AUDIT BUG: a fix that ADDS corpus rows transcribed the filing's 2-way aggregate "Other (1)" 123,565 under `revenue_other` — a key that in all 8 P1 periods means the companion-table RESIDUAL (filed 9M residual: 1,410). Every new row was column-pinned verbatim and the suite was green, yet the corpus now derives Q4 revenue_other = 1,937 − 123,565 = −121,628 and TTM revenue_other = −119,232: a negative revenue component from no filing, flowing as engine output. -> AUDIT RULE: when auditing ADDED data rows, verify the metric KEY's semantic consistency corpus-wide (what does this key mean in every other period?), not just the value's column-pinned verbatim fidelity. A verbatim-correct figure under a key with a different corpus-wide meaning is a P1.4-class source-discipline violation. Also: snapshot the TTM-unresolved metric inventory BEFORE and AFTER any data addition — newly resolvable metrics are new derived outputs and need identity/non-negativity gates re-run against them.
- [P2.1-R1] [Fix-Induced Defects] AUDIT PATTERN: the failure cycle 1 fix (add 9M income rows) itself introduced the cycle 2 defect. Remediation-directed data additions must be audited with the SAME rigor as original transcription — the review lens does not relax because "the fix was directed by OP". OP directives state the fix OBJECTIVE (make TTM resolvable); the transcription execution still gets the full data-gate treatment.
- [P2.2] [Tautological Identity Tests] AUDIT BUG: the roll-forward-closes test passed on every period while Q2 FY2026 additions were silently 0 and 9,000/5,009 of real economic movement (capex 7,028/5,587 + disposals) hid inside a "disposals_and_other" plug — because the plug was DEFINED as the roll-forward residual, the identity could never fail by construction. -> AUDIT RULE: an identity test over an expression containing a residual/plug term proves nothing about the components. Demand (a) explicit plug-value pins per period, (b) component==corpus-source equality asserts (additions == |CF capex row|), and (c) a tripwire (plug magnitude bound, e.g. plug > additions fails) — the 9,000 plug would have tripped instantly. Green tautology is the fixture-echo pattern wearing a different coat.
- [P2.2] [Period-Key Mismatch] AUDIT BUG: balance dates (`Q2 FY2026`) and cash-flow YTD spans (`6M FY2026`) live at DIFFERENT period keys in the corpus; an engine resolving CF inputs by balance-date key silently got null → additions 0 → plug absorbed the truth. Same class as P2.1's TTM-denominator fallback: unresolvable input silently degrades to green output. -> AUDIT RULE: any engine function joining two corpus families (balance×CF, income×KPI) must have its period-key mapping EXPLICIT and TESTED — a "missing CF row for a balance date" is an EngineError condition or a documented mapping, never a silent zero. Probe joins by printing each period's resolved source rows before trusting outputs.
- [P2.2] [Filed-Value Layering] AUDIT RULE: filed actuals (e.g. amortization-expense note totals) may never live as literals in engine code, however verbatim-correct — filed figures belong in the cited data layer with full source objects; the engine reads them like any other input. Grep engine files for bare numeric literals > 999 (outside comments) as a standing gate; exceptions must be structural or imported constants (e.g. DAYS_IN_YEAR from constants.js).
- [P3.1] [Workflow/Watcher] BUG: Attempted to run watcher via background `Start-Process` / detached PID. Detached processes return immediately to the LLM turn, leaving the agent dormant and unable to wake when DS submits. -> RULE: Watchers must ALWAYS run foreground-blocking directly within the active tool execution. Never use `Start-Process`, `&`, or background tasks. The synchronous exit (`seq > baselineSeq`, exit 0) is the sole event that wakes the agent for Step 2 audit.
- [P3.1] [Hybrid Mechanics] AUDIT BUG: Engine implemented hybrid FY2026 H2 as `FY estimate − H1 actual` with tests asserting full-year must not move when H1 actual moves — opposite of contract (`H2 = FY driver estimate − H1 driver estimate`, `value = H1 actual + H2` so H1 surprise flows into full-year). Material divergence ≈ 3,744 (subscription FY2026 1,034,821 vs contract 1,031,077.23) cascaded into every FY2026 line + downstream P3.2 CF/BS. -> AUDIT RULE: Hybrid semantics are a contract-identity check, not a plausibility check — independently recompute the join from raw corpus (Q1+Q2 actuals) + the driver model (modeled mid-year path) and pin the full-year value (anti-tautology), then assert the test's expected movement direction matches the contract's "surprise flows into year" wording.
- [P3.2] [Post-PASS Disclosure] AUDIT BUG: `forecast.js` (≈897 ln → rewritten 18:26) and `schedules.js` (single `historical` passthrough line) were rewritten AFTER P3.1 PASS (17:21) and the P3.2 submission disclosed nothing — the payload-first/signal-second invariant held, but the disclosure invariant did not. -> AUDIT RULE: Any file write after a PASS verdict must be disclosed in the next submission with a one-line diff summary (additive vs corrective, frozen-surface impact). Omission is a FAIL-class defect even when the diff is additive/benign — verify by `git diff v1.0-P3` vs `v1.0-P2` at gate, not by submission text alone.
- [P3.2] [Frozen Surface] AUDIT PATTERN: `threeStatement.project` needed corpus access but its frozen 3-arg signature could not be changed — the fix added a `historical` passthrough on `ScheduleSet`/`ForecastOutput` instead of breaking the signature. -> RULE: When an engine signature is frozen, corpus/plumbing needs flow through frozen containers (passthrough fields), not signature edits. After PASS, `schedules.build` shape is frozen INCLUDING `historical` — further shape changes need OP ruling and an explicit amendment to the contract's frozen-surface list.
- [P3.3] [Scenarios] AUDIT PATTERN: `scenarios.apply` used `?? 0` delta fallbacks at lines 90–92 — ruled compliant because `SCHEMAS.assumptionDriver` requires finite `bear`/`bull` at load (`ConfigError` on missing/non-finite), so the fallback is a defensive guard on a dead path paired with the typed `invalid_scenario_delta` throw. -> RULE: A `?? 0` / `|| 0` in scenario code is not automatically a silent-fallback violation — audit the load-time schema that guards it. If the load fails closed on missing deltas, the fallback is compliant defense; if the load permits absent deltas, the same line is a fail-closed violation. Record the reasoning.
- [P3.3] [Watcher/Re-arm] AUDIT BUG: OP issued P3.2 PASS (19:05) and omitted the re-arm call; watcher is session-scoped and does not survive host exit, so DS's P3.3 submission (20:40–20:41) landed cold and required §2.1 reconciliation + Director prompt "3.3 is here" to recover. -> RULE: Every verdict turn ends with the re-arm call (`node tools/watch_op_inbox.mjs` baseline `status_op.json.seq`) — no exceptions. The recovery path (inbox blocks > seq) works, but costs Director trust and gate time; encode the re-arm as the final checklist item on every verdict, including Gate Passes where the next watcher is deliberately NOT armed (state it explicitly).

### Quality Gate & Audit Best Practices
- [P0.0] [Code Review] RULE: Never trust submission text alone — perform line-by-line inspection of every modified file.
- [P0.0] [Test Verification] RULE: Independently execute the test suite; verify reported test count matches actual test runner output.
- [P0.0] [Boundary Checks] AUDIT PATTERN: Write standalone probe scripts in `scratch/` to test complex mathematical algorithms, data parsers, and edge cases.
- [P0.0] [Resource Safety] AUDIT RULE: Check for open file descriptors, dangling timers, and event listener leaks in test suites and service classes.
- [P0.0] [Visual / UI Deliverables] AUDIT RULE: If a sub-phase touches UI/visual presentation, inspect screenshots in `docs/screenshots/phase_X/v(n)/` against `docs/design_references/`. Blind code-only approvals are prohibited.
- [P1.1] [Table Layouts] AUDIT PATTERN: SEC filings interleave `$` separators between columns and vary labels per period ("Income (loss) from operations", "(Benefit from) provision for income taxes", footnote markers "(1)(2)"); map period?column by numeric-sequence position per filing, normalize labels, and exclude MD&A (tables with `% Change`/`Constant Currency` columns) and %-of-revenue tables ("100 %" cells). Cached filing HTML lives in scratch/op_p1_1_edgar/.
